# 04 — UI: Flux UI, Tailwind, Alpine.js, Acessibilidade

## Flux UI 2

Sempre priorizar componentes oficiais do Flux em vez de reinventar — reinventar quebra consistência visual e joga fora acessibilidade já resolvida pelo pacote.

**Requisitos** (doc oficial): Laravel 10+, Livewire 3.7+, **Tailwind CSS 4.2+**.

**Setup**:

```bash
composer require livewire/flux
```

```css
/* resources/css/app.css */
@import 'tailwindcss';
@import '../../vendor/livewire/flux/dist/flux.css';
@custom-variant dark (&:where(.dark, .dark *));
```

No layout: `@fluxAppearance` dentro do `<head>` e `@fluxScripts` antes do `</body>`. Tailwind v4 é CSS-first — não criar `tailwind.config.js` para isso. Flux Pro se ativa com `php artisan flux:activate` (e-mail + license key).

**Componentes do tier gratuito** (Flux 2.x — confira `vendor/livewire/flux/stubs/resources/views/flux/` no projeto, é a lista autoritativa):

`accent`, `aside`, `avatar`, `badge`, `brand`, `breadcrumbs`, `button`, `callout`, `card`, `checkbox`, `container`, `dropdown`, `field`/`fieldset`/`label`/`legend`/`description`/`error`, `footer`, `header`, `heading`/`subheading`, `icon`, `input`, `link`, `main`, `menu`, `modal`, `navbar`, `navlist`, `navmenu`, `otp`, `pagination`, `profile`, `progress`, `radio`, `select`, `separator`, `sidebar`, `skeleton`, `spacer`, `switch`, `table`, `text`, `textarea`, `toast`, `tooltip`.

O que **não** está nessa lista é Pro (date picker, calendar, editor, charts, autocomplete, command palette, tabs, accordion, etc.). Antes de escrever `<flux:algo>` que não esteja na lista, confirmar se o projeto tem `livewire/flux-pro` instalado — senão o componente simplesmente não existe e a página quebra.

## Tailwind CSS v4

Sempre utilizar:
- Utility First — nunca escrever CSS customizado quando um utilitário resolve
- Mobile First — construir a partir do menor breakpoint
- Dark Mode (`dark:`) em toda interface nova
- Design Tokens consistentes (cores, espaçamentos) — evitar valores mágicos (`mt-[13px]`) fora da escala padrão
- Componentização (extrair para Blade component/Livewire quando um padrão de classes se repete)
- Responsividade em todo componente

Tailwind v4 é **CSS-first**: tema via `@theme` diretamente no CSS em vez de `tailwind.config.js`; os design tokens ficam disponíveis nativamente como CSS Custom Properties. Diretivas que substituem o config JS: `@theme` (tokens), `@source` (arquivos extras a escanear, ex.: stubs de pacote em `vendor/`), `@custom-variant` (variantes como o `dark` acima), `@utility` (utilitário próprio), `@plugin` (plugin JS legado). Instalação no Vite é via `@tailwindcss/vite`. Ao gerar setup novo, não criar `tailwind.config.js` a menos que exista dependência que só o formato JS resolve.

## Alpine.js

Utilizar somente para:
- Interações locais: dropdowns, modais, tabs, menus, pequenas animações
- Estado de UI efêmero que não precisa ir ao servidor

Diretivas a dominar: `x-data`, `x-show`, `x-bind`, `x-model`, `x-transition`, `x-effect`, `x-ref`, `x-id`, Stores globais (`Alpine.store`), plugins (`Persist`, `Collapse`, `Focus`, `Morph`, `Intersect`).

Alpine já vem embarcado no bundle do Livewire — não instalar/incluir Alpine separadamente em projeto Livewire, isso causa dupla inicialização.

Transições: para elemento que aparece/some numa atualização do Livewire, `wire:transition` (View Transitions API nativa) é o caminho; a própria doc do Livewire manda cair para `x-transition` do Alpine quando a animação é mais complexa do que a View Transitions API resolve.

Nunca duplicar regra de negócio já existente no backend — Alpine é para UI, não para lógica de domínio.

## Acessibilidade e UX

Toda interface deve possuir:
- Loading States (idealmente Skeleton Loading, não só spinner genérico)
- Empty States com mensagem clara e ação sugerida quando aplicável
- Feedback visual em toda ação (toast/alert do Flux)
- Mensagens de erro/validação claras e associadas ao campo
- Responsividade completa (mobile first)
- Acessibilidade WCAG: labels associados a inputs, contraste adequado, navegação por teclado, `aria-*` quando o componente não é nativo
- Dark Mode funcional, não só "não quebrado"
